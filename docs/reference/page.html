Quality

How well the agents back what they write. A claim is one factual list item, table row or paragraph; it is unsourced when it cites nothing checkable (a file and line, a query, an MR, a commit, a build, an artifact, a link). Counted by infra/quality/claims.py on what was actually posted. The analyst's fresh checker (a separate reviewer that opens every cited source) adds how many claims held up.

For agents

Keeping this page current

This page is generated. Its text lives in the repo, so a change and its documentation land in the same merge request.

  1. Edit the matching file under docs/reference/sections/ in the same branch as the change (new component → add it; changed behaviour → update it; removed → delete it).
  2. After the merge, on the agent host: git -C /srv/agent-ops pull, then uv run --with markdown --with pyyaml python docs/reference/build.py (with the env file loaded; --offline builds from the repo alone).
  3. Publish docs/reference/out/index.html wherever your team reads docs: a static site, an internal wiki that takes HTML, or a private Claude artifact. The timeline and reports rebuild themselves.
  4. Schedule steps 2–3 daily so the reports never go stale.

The build refuses to write anything that still contains an email or IP address. Service agents can't publish artifacts (guard rule 8); only a person's session or a scheduled job publishes.
